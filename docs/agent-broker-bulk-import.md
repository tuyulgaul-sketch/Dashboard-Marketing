# Agent and Broker bulk import — approved requirement

Requested 8 September 2026 for Marketing Administration. This is a requirements document, not an implemented feature or authorization to import the attached records.

## Scope
Add bulk XLSX/CSV upload to the existing Agent and Broker Master screens, retaining the existing single-record add/edit functionality. Use the existing centralized Supabase master_agents and master_brokers tables, not a second database or browser-local master. Do not modify existing business records as part of deployment. The existing role/authorization policy remains authoritative; no permissions via Login As or UI-only checks.

## Source formats
Daftar Agent.xlsx, Sheet1, exact columns: No.; Kode Agen; Nama Agen Asuransi; Perusahaan Asuransi; Nomor Lisensi; Tanggal Lisensi; Tanggal Masa Berlaku Lisensi; Email; Status. Eight populated records. Agent identity is Kode Agen; also check license number and other existing-master collisions. Preserve codes and license numbers as text and leading zeros. Validate calendar dates, expiry >= license date, email when supplied, and explicit status mapping AKTIF/Active and TIDAK AKTIF/Inactive. An expired license must not silently be treated as authorized to transact.

Daftar Broker.xlsx, sheet Perusahaan Pialang Asuransi, exact columns: Nomor; Nama Perusahaan; Nomor Izin Usaha; Tanggal Izin Usaha; Alamat; Kota; Kode Pos; Nomor Telepon 1; Nomor Telepon 2; Nomor Fax; Alamat Email; Website. 150 populated records. Broker identity and matching must use verified company/legal identity and license, not an assumed row number. The source contains one repeated license number, KEP-156/KM.13/1991, on rows 86 and 129 for two different companies. Flag both for manual reconciliation rather than selecting one or merging automatically. The file has no status column; do not infer current regulatory authorization or set all rows Active solely from the source. Existing official status remains authoritative until explicitly reviewed.

Accept original XLSX files as supplied, including Excel serial dates, dd-mm-yyyy text dates, blank optional cells, formula-safe text, line breaks, and placeholder '-' values. Reject invalid file types, duplicate required headers, missing required fields, unsafe formula results, invalid dates, and excessive file/row sizes. Use the shared browser-compatible workbook reader, with regression fixtures derived from the original files but containing no real personal details.

## Workflow
Existing Master Agent and Master Broker screens each receive Download Template, Upload XLSX/CSV, Validate, row-level preview, and explicit Import confirmation. Keep single add/edit/delete unchanged. Show created, existing/skipped, conflicts, invalid rows and exact row-level reasons. Duplicate keys inside the file or against current DB are not silently inserted or overwritten. Default mode is add-new only; updating existing records requires a separate explicitly reviewed operation that preserves stable IDs and linked records. Never replace the entire baseline for this workflow. Re-read current master and revalidate before committing. Preserve full contact and license metadata, original source file/batch/row provenance, actor, timestamp and audit history. Provide an error report for correction and reupload. Use a server-side authorization check and transaction-safe batch write/idempotency, not a loop of fire-and-forget store writes. Prevent unauthorized or partial writes and handle concurrent imports safely.
